## Summary

This is the first full-codebase baseline. All four baseline gates pass, and the headless simulation is deterministic across repeated runs. The review records 64 findings. Two are closed by documentation fixes on this branch, leaving 62 open: 1 P0, 1 P1, 16 P2 and 44 P3. Twenty-one of the open findings were reproduced (Verified); the rest are inspection findings (Read).

The P0 is `browser-log-only-persisted-on-pause`. The browser host writes its event log to storage only on an explicit Pause, a timeline operation, or worker startup. If the player reloads, closes the tab or crashes without pausing first, everything since the last pause is lost, and the whole run is lost if they never paused. This was reproduced in Chromium and against `NodeHost`. The P1 is `run-start-overwrites-without-confirm`: Start replaces the active run immediately, with no confirmation.

The rest cluster in a few areas:

- **Event-log replay fidelity.** Rejected commands are logged and can behave differently on replay, and `step` replays differently from live play.
- **Worker error propagation.** Failed queries never get a reply.
- **Intervention rules on extinct lineages.**
- **UI projection drift.** The UI's projected state can disagree with the host after retries or rejected commands.
- **Tooling that assumes a single checkout.** This breaks under the mandated worktree workflow.

Thirty-one findings are promoted into twelve backlog entries. The remaining 31 open findings are kept as inventory.

## Invariants

These held at `9b37eed` and are the reference for incremental reviews:

- `sim/` imports only its own modules and type-only `protocol/types.js`. It uses no DOM, Node API, `Date`, `performance` or `Math.random`, and ESLint enforces the main cases (`eslint.config.js:31-91`).
- Probabilities are u64 thresholds, and simulation accounting is integer-only. PRNG draws depend only on documented conditions, and quarantine funding consumes none.
- `snapshot`/`restore` round-trip all 14 `SimState` fields. This includes PRNG state, quarantine insertion order, decree and patch order, and Map insertion order for probes and lineages.
- Diffusion conserves total resources exactly and never produces negative cells.
- Proto field numbers are not reused, and the 15 `SimEvent` kinds match the proto oneof. Protocol messages are plain data.
- Log entries are ordered by `(tick, seq)`. Rewind keeps entries at or before the target and resumes the sequence after them, and replay skips save, deleteSave, switchRun and deleteRun.
- Switch, rewind and load prepare state in an isolated host. On failure the live state, writer, marker and log stay unchanged and the run stays paused. Concurrent commands are rejected without being logged.
- `NodeStorage` writes atomically (temp file and rename). OPFS writes use writable swaps, and event-log flushes are serialised per writer.
- The stdio codec revives every bigint field in commands, queries and events. Query results are the exception (`ndjson-codec-missing-result-revival`).
- UI store selectors return stored fields or primitives. Every interval, timeout and listener in the components is cleaned up. Stale query replies are guarded by transport, timeline epoch or call order.
- All 20 scripts are executable, use `set -euo pipefail`, and propagate failure. `check.sh` stops at the first failed gate, and Vitest has `passWithNoTests: false`.
- Every tracked `*.test.ts` file is inside the Vitest include. All four goldens are consumed by `test/determinism/golden.test.ts`, and a missing golden throws.
- CI reads `.nvmrc`, installs with `--frozen-lockfile`, cancels only superseded PR runs, and uploads browser evidence on failure. Scheduled validation compares two CLI runs per seed and fails on a mismatch.

- `browser-log-only-persisted-on-pause` — **The browser persists the run's event log only on an explicit Pause, so a reload, tab close or crash while running loses the run.** Bug · Open · Verified.
  - Where:
    - `host/worker.ts:217`: the only per-command flush, for `pause`. The other is at startup, `host/worker.ts:82`.
    - `host/node.ts:1155-1161`: auto-pause sets `paused` without flushing, and the worker never learns about it.
    - `host/node.ts:1193-1205` (`scheduleSnapshot`) writes the snapshot file but only buffers its `snap` entry.
    - `host/event-log.ts:109-145` (`EventLogWriter`) keeps every entry in memory until a flush.
  - Severity: P0.
  - Gaps: the UI pauses, and so flushes, before Save, Load, Switch run, the patch editor and the decree composer (`ui/components/RunPanel.tsx:55,60,70`, `ui/components/PatchEditorModal.tsx:100`, `ui/components/DecreeComposerModal.tsx:82`). What is never written is:
    - play that is never paused;
    - commands issued while paused, such as patches, decrees, quarantine and steps, if the player reloads before pausing again;
    - everything after an auto-pause.
  - Failure: `newRun` queues a delete of the slot's log (`host/node.ts:1074-1077`) and its new entries stay buffered. On reload, the startup `switchRun` reads an empty log and installs a fresh writer (`host/node.ts:1606`). Its acknowledgement (`host/node.ts:1625`) is logged into that writer, and the startup `flush()` (`host/worker.ts:82`) writes it. `runs/default/log.ndjson` then holds a single 119-byte acknowledgement line, so `lastModifiedMs` is non-zero and `bootstrapRun` takes the restore branch (`ui/sim-store.ts:757-762`). The player sees an empty, paused run at tick 0. The lost run's snapshot files stay on disk but nothing references them.
  - Chromium reproduction: seed 2026 ran to tick 308 without pausing. After a reload the dashboard showed tick 0, paused, and Switch run listed only `default` at tick 0. In a `NodeHost` reproduction that mirrors the worker (startup switchRun and flush, newRun, 500 unpaused ticks, a second startup), the second host's `currentTick()` was `null`. Its log was exactly that 119-byte acknowledgement, and `0.snap` was still on disk.
  - Docs: this contradicts README.md:24, ARCHITECTURE.md:41 and `host/event-log.ts:104-108`. The reload e2e tests pause first (`e2e/dashboard.spec.ts:51,74`), so they cannot catch it.
  - Correction: flush on a bounded cadence, after each snapshot and command, and on auto-pause. Consider pausing and flushing on `pagehide`. Named saves are separate files and survive.
  - Review backlog: `browser-run-log-durability`
